## 近期变更总览

### 红包监听

- Dashboard 增加“抢红包”工作区，可设置总开关、参与账号和最低红包金额。
- 监听范围固定为 `@ja_netfilter_group` 的话题 `458347`，同时处理新消息和编辑消息，只点击“抢红包” callback 按钮。
- 主号和副号复用现有 Telegram 客户端；小号和 Waaiging 在游戏脚本因公开群保护停用时，会在原 tmux 窗口切换为红包待命模式。
- 金额无法识别、低于阈值或按钮类型不是 callback 时不会点击；每个账号持久化已处理消息 ID，避免重启或消息编辑造成重复点击。

### 跨账号控制与健康监控

- `0` / `1`、`.0` / `.1`、`止` / `启` 已统一为三套脚本的暂停/恢复控制，只接受配置中的授权管理员或授权群组消息；未授权来源会记录日志并忽略。
- 主号、副号、小号都加入健康 watchdog：调度任务异常退出、关键到期项长期未推进，或身份发送锁长时间占用，会触发进程重启保护。
- 三套脚本会把最近一次游戏机器人活动写入共享文件 `bot_activity_shared.json`；任一脚本刚看到机器人消息时，其他脚本发送前会通过共享状态认定 bot 没有全局失联，避免单进程本地状态过期导致误停。
- 发送任何普通指令前都会等待游戏 bot 活跃；如果三套脚本共享记录都已过期，会判定更像机器人维护或全局失联，只在本地限流记录等待状态，不继续向群里刷指令。
- 共享状态还会记录最近一个真实玩家点号指令和后续命令回执；带 `.` 的指令超过 30 秒没有回执时，即使游戏 bot 仍有普通消息活动，也会按维护/静默处理并停止继续发指令。
- 连续无响应触发健康暂停时会写入共享 maintenance 状态；只有命令回执会解除点号指令静默，普通 bot 活动不会清掉这类维护判断。watchdog 在共享维护或正在等待 bot 活跃时会延后 stale due / `avatar_send_lock` 重启，避免维护期间反复重启。
- 真正的调度任务异常退出仍会立刻触发 watchdog 重启；维护等待只保护机器人无响应导致的发送等待，不掩盖 scheduler task 已停止的问题。
- Dashboard 的自动化排程和启动就绪状态已修正；本地改代码后仍必须部署到 VPS 并重启对应 tmux，不能只看本地测试。
- 命令守卫会对短时间重复失败、机器人无回复、身份暂停和 dashboard 禁用做退避；业务逻辑遇到无法识别的回执必须保守等待或告警，不能连续刷同一指令。

### 追赶调度与日常任务优先级

- 维护恢复或脚本重启后，已到期的收益型冷却任务优先补跑；`.宗门点卯`、`.观命`、`.定命` 视为低优先级日常一次性任务。
- 如果任一身份存在已到期的非日常冷却或重试任务，日常一次性任务会先让路，避免恢复后点卯等低收益任务抢队刷屏。
- 主号化身循环先处理元婴/裂缝、阵法和侍妾链，再处理点卯、观命/定命；副号与小号化身也把点卯放在本轮靠后位置。
- 主号“等待最近到期任务”的判断不会因为只有纯日常任务到期就强行归零，避免日常任务把高收益追赶窗口挤掉。

### 身份与宗门安全

- 主号和小号主魂是万灵宗；小号问心子是凌霄宫；同名缘生子在主号/副号是阴罗宗，在小号是太一门。所有宗门指令必须按上面的身份与宗门表判断。
- 小号问心子的凌霄宫指令会强制新鲜切换身份；如果回执显示宗门不符或身份不对，不记录成功，后续会重新确认身份。
- 天星宗身份执行 `.探寻裂缝` 前会依次发送 `.推命 探索`、`.改命 探索`，按身份宗门映射统一判断，不按账号或昵称硬编码；野外历练不会因此恢复这两个前置。
- 阴罗宗相关指令需要同步到对应身份。化功为煞失败后必须解析回执里的冷却时间并等待；解析不到时使用保守兜底冷却，不能疯狂重试。
- 南宫婉/解咒委托链路只由主号主魂和小号主魂发布：每天 09:00 左右 `.探望南宫婉`，每 8 小时按 `.推演封魂咒` → `.护持神魂` → `.发布解咒委托 1` 执行；主号委托由主号缘生子接取，小号委托通过共享状态交给副号缘生子接取。主号主魂额外执行 `.婉影问安`（每日一次）和 `.同参封魂`（8 小时一次），不会同步到小号。
- 阴罗宗接取解咒委托后按 `.辨认咒纹 @委托用户`、`.借幡镇魂 @委托用户`、`.剥离咒源 @委托用户` 顺序执行；遇到煞气不足先用 `.化功为煞 10000` 补煞再重试原步骤；整条解咒下一轮冷却以最后一次成功 `.剥离咒源` 的时间为准。发布回执里的新委托 ID 和“已有进行中 ID”都要解析记录，不能重复刷发布。
- 通过 `.红尘寻缘` 寻找南宫婉的目标侍妾链路已停用；脚本不会再为了重抽侍妾自动发送 `.红尘寻缘` 或 `.遣散侍妾`。

### 周期收益日报

- 三套脚本都会记录周期收益事件并生成日报；账号名保持 `主号`、`副号`、`小号`，不要把副号误改成小号。
- 日报解析已覆盖元婴/元神、探寻裂缝、野外历练、登天阶、收集精华、灵兽探渊、问道等结算；编辑后的最终结算也会补记。
- 解析时会过滤状态标题、天命前缀、灵兽名等非奖励文本；无数量的括号奖励按 1 计数；重复事件会去重，旧的野外历练事件会在汇总时按新规则重算。
- 失败类结算也会记录成失败事件，但没有奖励时不强行制造奖励项。
- Telegram 日报使用 MarkdownV2，展示为“账号明细 + 时间线”：每个身份先给出有效/结算/成功/脱险/失败和收益合计，再列出每条结算的时间、结果和奖励；野外历练的推命命中会在日报里显示天机与贡献，改命脱险单独计为“脱险”。
- 日报 Telegram 推送默认关闭，不再自动发到 `notify_target`/Waaiging；需要临时恢复时在配置里显式设置 `"daily_reward_summary_push": true`。
- 周期收益事件会同步写入 `message_events.sqlite3` 的 `daily_reward_events` 表，Dashboard 的“周期收益日志”可按日期、脚本、身份和指令筛选查看。

### 观星与改换星移

- `观星台`、`安抚星辰`、`收集精华`、`牵引星辰` 已改由 miniapp 操作，聊天指令入口停用；脚本和 Dashboard 都不再自动发送或展示这组命令。
- 观星不是每个整点都无条件发送；只在目标 Good 显化窗口或每日 `23:59` 兜底时发送。`00:00` 没有目标机会时不会硬发 `.观星`。
- 三账号错开改换星移窗口：主号 `素缘子` 走早窗，副号 `厚土` / `寻真子` 走中窗，小号 `素心子` 走稍晚动态窗，避免同一轮互相抢占。
- 每次 Good 显化只派一个轮换化身观星；如果 Good 消息已经处在活跃窗口内，会立即发送 `.观星`。
- 如果后续星盘变成 Bad/Neutral，或最终报告已经结算，会取消待发送的 `.观星`，不消耗当天机会；被动观星结果也能反向标记当天已观星。

### 万灵宗灵兽自动化

- 主号灵兽列表和体力已迁移到万兽谷 Mini App；脚本使用配置中的固定 `startapp` 入口获取 Telegram WebView 签名，再读取 `/api/miniapp/xianxia-spirit-beast/start`，不会向群里发送 `.我的灵兽` 或 `.洞府`。
- 主号自动同步每日最多 2 次，两次之间至少间隔 30 分钟；次日自动重置配额。Dashboard 手动刷新不占自动配额。万兽谷子令牌保存在权限为 `0600` 的 `miniapp_beast_session.json`，不写入 Dashboard 会返回的 state。
- Dashboard 的“我的灵兽”入口已替换为“万兽谷同步”，显示最近同步时间、灵兽数量和接口错误；刷新按钮通过本地请求文件唤醒主号，不发送聊天指令。
- 公开群受限期间，小号主魂也只通过固定 Mini App 入口同步万兽谷状态，每 12 小时一次；不会发送 `.我的灵兽`、`.洞府` 或任何灵兽聊天指令。
- 万兽谷 Mini App 当前没有旧版“灵兽巡边/巡边归来”接口，因此受限模式只同步灵兽列表和体力，不会把新“行迹/远征”接口冒充旧巡边执行。
- 小号主魂的灵兽循环优先级是：探渊 6 小时、偷菜 4 小时、六翼放养恢复、灵兽巡边 75 分钟、常规一键放养 4 小时、灵兽互动 90 分钟、灵兽巡游 120 分钟。
- 六翼优先执行探渊和偷菜，自动巡边始终改用其他可用灵兽；偷菜处于“锁定目标/准备动手”阶段时不会提前放养，结算后才放养恢复。
- 灵兽巡边使用 `.灵兽巡边 <灵兽名> <斥候/护粮/袭营>`，默认 `袭营`；`.巡边状态` 用于同步已有巡边和剩余时间，`.巡边归来` 用于召回。
- 没有休息中的灵兽时，先召回体力最高的一只；巡边归来后要继续尝试下一轮巡边。体力不足失败时要换其他候选灵兽，不要卡在同一只。
- Mini App 刷新时要保留本地已知的巡边流程；如果聊天回执提示已有灵兽在巡边或灵兽正忙，仍要反向同步状态。
- 探渊、偷菜、放养、巡边、巡游都要记录灵兽状态，避免同一只灵兽被多个任务同时使用。
- `.我的灵兽` 已废弃，主号不得再自动发送。Mini App 同步失败时只保留旧缓存用于展示，不用旧体力启动新的灵兽动作；接口恢复后自动重试。
- 六翼是重点保护灵兽：探渊结算成功后立刻尝试一次 `.一键放养`；如果回执提示休养、冷却或暂不可放养，则解析等待时间后重排，解析不到时按 30 分钟兜底等待。

### 群组可见性联动受限账号

- 主号脚本负责监控游戏群是否有有效公开用户名；有公开用户名视为公开群，没有公开用户名（仅邀请链接可加入）视为私密群。
- 游戏群变为私密群时，主号自动确保 `xiuxian:2` 小号和 `xiuxian:3` Waaiging 运行完整脚本；变为公开群时会停止完整群指令脚本，并在原窗口启动红包 + Mini App worker。
- 两个完整脚本都会轮询自身写权限；遇到禁言或 `CHAT_WRITE_FORBIDDEN` 时立即退出，主号随后在原窗口启动红包 + Mini App worker，并按既有间隔继续探测能否恢复完整脚本。
- 在主号配置的 `monitor.restricted_accounts` 中配置脚本、tmux 窗口、state 文件和轮询间隔（最低 15 秒）。
- `@Waaiging` 固定为天星宗主魂且没有分身，野外历练固定使用 `.野外历练 深入`；脚本启动时会校验 session 用户名，避免误用其他账号的登录态。
- 如果游戏内仍是散修或处于叛宗冷却，脚本会暂停点卯并按机器人返回的冷却自动重试 `.拜入宗门 天星宗`；可在 state 中用 `sect_join_not_before` 设置准确的最早入宗时间，机器人返回的整小时剩余时间不会把计划提前。只有入宗成功后才启用天星宗专属身份逻辑。

## 必要工作流程

真实运行环境在 VPS：`ubuntu@VPS_HOST:/home/ubuntu/deploy`。本地改完不代表线上已生效。

1. 修改前查看 `git status --short --branch`，必要时先查 VPS 日志或 state。
2. 本地修改代码，优先复用通用模块。
3. 本地运行 `python -m py_compile ...` 和相关测试。
4. 用 `scp -O -i C:\path\to\vps-key.pem` 上传改动文件到 VPS。
5. 在 VPS 用 `/home/ubuntu/deploy/venv/bin/python -m py_compile ...` 复查。
6. 重启对应 tmux：`xiuxian:0` 主号，`xiuxian:1` 副号，`xiuxian:2` 小号，`xiuxian:3` Waaiging，`xiuxian:4` dashboard。
7. 检查 VPS 进程、tmux、日志或 dashboard，确认线上已生效。
8. 将 VPS 上的 `state_*.json` 和 `*.log` 下载回本地覆盖，session 不下载。
9. 只 stage 本次相关文件，commit 并 push；如果不能提交或推送，必须明确说明原因。

SSH/SCP 必须显式带 key：

```powershell
ssh -i C:\path\to\vps-key.pem ubuntu@VPS_HOST
scp -O -i C:\path\to\vps-key.pem .\changed_file.py ubuntu@VPS_HOST:/home/ubuntu/deploy/
```
