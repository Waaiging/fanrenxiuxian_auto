## 本轮修正

原取窗代码把 `1` 传给 socket 超时，但请求前的故障保护排队不计入其中，发送、响应头和响应体也会重复使用完整超时。单次 socket 超时并不能约束整条取窗链路。

现在为每次 `/window` 尝试建立共同截止时间：

1. 请求前等待耗尽 1 秒预算后，直接返回本地读取超时，不再发出该请求。
2. 发送、响应头、响应体读取依次使用剩余时间；响应体分段读取，避免每段重新获得完整一秒。未读完或长度不完整的连接关闭，不放回连接池。
3. 继续按原游标和 360ms 轮询节奏读取；保留故障保护、半开探测、单次攻击及结算策略。
4. 诊断升级 v8，逐行脱敏保留取窗 `attempts`，记录预算耗尽阶段，同时保留 v7 的轮询分段统计。

新增回归先在旧代码上复现 5 个失败条目（含探测子用例），覆盖排队超限、累计读取超时及诊断丢失。验证还覆盖健康回执、半开探测、既有攻击超时，以及本机 HTTP 的连接复用、分块、关闭和截断响应。测试使用隔离副本、模拟时钟或本机服务器，没有人工触发游戏参战或攻击。

该修正可以避免排队耗尽后继续消耗一个网络读取周期，实际能补回多少窗口仍须后续自然开场验证。线程失去调度、DNS 或响应头内部读取等阶段仍可能晚于本地截止时间返回，剩余预算会在重新获得执行机会时检查；不能承诺所有请求都在墙钟一秒内结束。
