# 2026-09-08 项目复盘

## 结论与范围

本轮覆盖四账号与受限待机入口、指令发送和回复匹配、共享状态、定时任务、风雷翅收尾、身份重生、Mini App 垂钓、Dashboard 认证、测试与部署。审查采用源码核对、运行拓扑及文件哈希比对、故障场景回归；不等于穷尽所有业务分支。

项目已有共享发送入口、原子 JSON 持久化、Mini App 传输熔断和模块化业务组件，适合继续按故障边界拆分。当前主要问题是共享状态并发、业务成功确认和版本漂移，整体重写会同时改变四账号身份、调度和游戏协议，收益不足以覆盖风险。

## 测试与版本

复盘开始时，本地已有 32 个修改文件。生产业务 Python 与这些修改后的本地版本一致，但 Git HEAD 尚未包含全部已部署改动。所有原文件和差异均先备份，再核对回流；不回退已经上线的业务设置与功能。

本地旧全量基线为 1066 项，25 个失败、9 个错误、12 个跳过。主要原因是退役聊天功能的旧测试、观星提前量旧预期和测试依赖真实身份设置，另有真实身份回滚问题。删除了 7 个调用已退役方法的用例，其余按现行业务契约修复或隔离；没有恢复退役功能，没有失败白名单。

VPS 与本地测试亦有漂移。本轮按 AST 比对测试方法，区分历史道号替换、旧版用例和新增覆盖，合并线上独有的 10 个观星、垂钓测试，保留本地更新的覆盖。发布测试集与提交版本保持一致。

新增隔离测试入口 `tools/run_tests.py`，测试子进程不带真实 `.env`、配置、state 或 session；失败、错误和零测试均使命令失败。CI 使用 Linux Python 3.12、Windows Python 3.14。直接依赖固定到 VPS 已安装版本，测试单独包含 `httpx`。

本地 Python 3.14.3 与 VPS Python 3.12.3 的完整隔离测试均通过 1091 项，0 失败、0 错误、12 项既有跳过，分别约 240 秒、227 秒。CI 首次 Windows 运行额外暴露了未声明的 `tzdata` 依赖，已补充 Windows 平台条件依赖，避免干净安装后读取 `Asia/Shanghai` 时区失败。最终候选版本和 CI 结果随发布台账留存。

## 运维

移除了已失效的 `deploy-vps.yml`：它假定线上是 Git 工作区、关闭 SSH 主机身份校验，且只重启三个账号。CI 负责测试，生产发布继续使用暂存、哈希保护、备份、验证、原子替换和按当前运行模式重启的流程。

四 worker 使用 `xiuxian:0..3`。复盘时 Dashboard 是独立进程，窗口 4 已退出，窗口 5 是世界 Boss 验证器。重启前必须识别实际进程及受限模式；部署共享模块需要重启其使用者，保留验证器，避开进行中的战斗。

发布后的实际提交、文件 SHA256、备份路径、Python 3.12 / 3.14 测试结果、进程和 HTTP 检查以运行目录的 `deploy_version.json` 为准。发布验证只读，不额外发送 Telegram 测试指令或触发游戏操作。

## 后续重构顺序

1. 将账号脚本中的解析器、纯状态迁移逐个拆为独立模块，先保留现有入口和数据字段。核心文件仍有约 6000 至 7700 行，避免一轮修改同时重做调度和协议。
2. 统一耗尽资源、服务端冷却、传输故障的重排结果类型，明确每种失败由哪一层重试。优先扩展已有小世界资源估算与垂钓退避模式，避免多层重试相乘。
3. 梳理同步文件锁对异步事件循环的阻塞。`state_io` 的进程内 `RLock` 不代表底层文件锁可嵌套重入，调用方应避免嵌套；Mini App Linux 锁也有无超时等待路径，需独立设计和竞争测试后迁移。
4. Dashboard 继续增加状态修改请求的 Origin 校验并评估旧 Basic 认证的退出。当前限速在单进程内生效，重启会清空；多进程部署需要共享限速存储。
5. 在依赖升级任务中锁定传递依赖；将发布清单、安装和回滚流程收敛为可复用工具，并给发布锁、进程交接增加故障注入测试。

## 验证边界

此前的 Linux Do 群异常涉及 Telegram 上游传输，源码重构无法修复群所在数据中心或 Telegram 服务端故障。游戏机器人文字和 Mini App 接口仍可能变化，模拟回归不能替代下一次真实定时事件的运行日志。不要用自动化测试成功推断所有线上事件已成功执行。
